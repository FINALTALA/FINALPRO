# VIA Admin — morning manual acceptance checklist

**DEV READ** means browse, filter, preview or export existing data with authorized accounts. **ISOLATED** means use disposable DB, Redis and media with test accounts. Intentional editorial work on development requires the operator’s decision and falls outside the read-only checks.

Record route, role, locale, browser/version, viewport, fixture or record ID, expected/actual result and PASS, FAIL, UNVERIFIED or BLOCKED. Capture one useful screenshot or request status per check. Mask personal data, payment details, tokens and signed URLs.

| Module and routes | Click or do | Expected result and evidence | Development safety |
| --- | --- | --- | --- |
| Dashboard — `/admin` | Open as admin, inspect counts and follow quick links. Check relevant figures against the same date range in Analytics. | Counts reflect displayed definitions. Links reach the intended queues. Record cards, period and destination routes. | DEV READ. |
| Marketplace and verification — `/admin/vendors`, `/admin/vendors/[vendorId]`, `/admin/verification`, `/admin/verification/[vendorId]` | Filter stores and evidence. Compare physical branch and warehouse cases. Open the queue as a reviewer and inspect an eligible item. | Store status and evidence agree. Reviewer sees authorized review work with conflicts excluded. Record store ID, evidence kind and status. | DEV READ. Approve, reject and request resubmission in ISOLATED. |
| Offers and matching — `/admin/offers`, `/admin/offers/[offerId]`, `/admin/canonical-products`, `/admin/canonical-products/[id]`, `/admin/name-change-requests`, `/vendor/[vendorId]/match-review` | Search for an existing offer and inspect its hold state, canonical product and any matching or name-change request. | Seller offer, canonical reference and current decision state agree. Record offer/canonical IDs and status. | DEV READ. Hold, restore, match or approve in ISOLATED. |
| Marketplace supporting pages — `/admin/categories`, `/admin/brands`, `/admin/collections`, `/admin/size-guides`, `/admin/reviews`, `/admin/vendors/performance` | Open each list and one available detail. Inspect filters, empty states and any flag-disabled performance state. | Lists and detail agree. Disabled or empty states are explicit. Record route, visible state and one sample ID. | DEV READ. Taxonomy, moderation, collection and flag changes in ISOLATED. |
| Approval Center — `/admin/approvals`, `/admin/brands/requests`, `/admin/size-guides/requests` | Compare visible counts with source queues for branch, warehouse, name change, brand, reported review, return and size guide. Follow a source link as admin and reviewer. | Counts match comparable filters; unavailable differs from zero. Reviewer sees only authorized sources. Record count, role and linked route. | DEV READ. Submit source decisions in ISOLATED. |
| Orders and returns — `/admin/orders`, `/admin/orders/[orderId]`, `/admin/branch-orders`, `/admin/returns` | Search by order number. Open a cancelled/refunded order and one escalated return. Compare money, status and history. | Snapshots, refund figures and history agree; customer data is masked where expected. Record order/return IDs and totals. | DEV READ. Forced cancel, refund, exchange and return decisions in ISOLATED. |
| Users, roles and sessions — `/login`, `/admin/users`, `/admin/users/[userId]`, `/admin/settings` | With authorized existing accounts, compare admin and reviewer access. Inspect masked user details and team roles. | Unauthorized routes/data are refused. Admin detail displays expected role and account state. Record role, route and response. | DEV READ for inspection. Suspend, lift or force sign-out using ISOLATED accounts. |
| Analytics and exports — `/admin/analytics` | Select one fixed date range and compare Orders and Money to Dashboard where definitions match. Export CSV and XLSX for the same section. | Dates, filters, totals and metadata agree across UI and exports. POS stays separate. Record period, section, totals and filenames. | DEV READ. Handle exports as restricted data. Create refund/revenue fixtures only in ISOLATED. |
| Content Studio — `/admin/content`, `/admin/content/[page]` | Open HOMEPAGE, TRENDING, ADS, WOMEN, MEN and KIDS. Compare existing preview or built-in state with `/`, `/trending`, `/ads`, `/women`, `/men`, `/kids` in Arabic and English, desktop and phone. Verify a separate anonymous session sees public content. | Existing designs and catalogue blocks remain intact. Drafts stay private. Record managed/import status, current revision, overflow and screenshots. Men/Kids are pending import. | DEV READ. Draft save, publish/unpublish, schedules and revision restores in ISOLATED. Real imports or translation publication require a deliberate editorial decision. |
| Media Library — `/admin/media`, `/admin/media/[mediaId]` | Filter existing media, open detail, preview an image and play/seek a video where available. Check usage entries and lifecycle controls. | Preview loads; video plays and seeks; references and lifecycle state are visible. Record asset ID, format, browser and outcome, with signed URLs redacted. | DEV READ for existing assets. Manual image/video upload, invalid files, archive/restore/purge and public-delivery changes in ISOLATED. |
| Settings, flags, alerts and audit — `/admin/settings`, `/admin/feature-flags`, `/admin/alert-recipients`, `/admin/notifications`, `/admin/audit-logs` | Compare settings summary to flag and recipient lists. Find an existing audit event using filters and review its export if needed. | Registry values agree, alerts are scoped to the role, and audit records show the actor/action without sensitive payloads. Record flag key/state and audit ID. | DEV READ. Toggle flags, change recipients or acknowledge alerts with persisted state in ISOLATED. |
| Customer and merchant interactions — `/discovery`, `/cart`, `/checkout`, `/orders`, `/vendor/[vendorId]/verification`, `/vendor/[vendorId]/offers/[offerId]`, `/vendor/[vendorId]/orders` | Browse as customer and open existing order/cart views. As merchant, inspect evidence, order status and any visible hold reason. In isolation, exercise hold → correction → restore and customer search/cart/checkout, plus an order/return decision. | Held items are excluded from browse and checkout, merchant sees reason and can submit a permitted correction, and existing confirmed orders survive a hold. Record offer/order IDs, before/after states and denial status. | DEV READ for existing views. Adding cart items, reserving, placing orders, offering corrections or changing state in ISOLATED. |

**Closeout:** Track Trending’s 20 English suggestions, Ads eligibility, Men/Kids imports, manual media checks and Firefox/Safari/WebKit gaps separately. Record static Trending Pieces as a product decision. Preserve the existing design and keep paid campaigns deferred.
